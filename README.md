# Эмулятор оболочки ОС

Учебный проект по дисциплине «Конфигурационное управление» (вариант 26).
Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом и
виртуальной файловой системой (VFS), которая целиком хранится в памяти.

## 1. Общее описание

Программа открывает окно с областью вывода и строкой ввода. Пользователь
вводит команды, эмулятор разбирает их (с учётом кавычек) и выполняет.
Заголовок окна строится из реальных данных ОС: `Эмулятор - [user@host]`.

VFS загружается в память из директории на диске (`--vfs`). Все операции
выполняются только в памяти: файлы на диске не распаковываются и не
изменяются. Исключение - служебная команда `vfs-init`.

Реализовано на Python 3.10+ (только стандартная библиотека, GUI - tkinter).

## 2. Описание всех функций и настроек

### Параметры командной строки

- `--vfs PATH` - Директория на диске, из которой загружается VFS. Без параметра используется
  встроенная VFS по умолчанию
- `--prompt TEXT` - Приглашение к вводу. Можно использовать `{user}`, `{host}`, `{cwd}`. По
  умолчанию `{user}@{host}:{cwd}$ `
- `--script PATH` - Путь к стартовому скрипту

При запуске все заданные параметры и статистика загруженной VFS
выводятся в консоль и в окно (строки `[debug] ...`). Если значение
начинается с `-`, пишите `--prompt=-> `. Если директория VFS не найдена,
программа печатает ошибку и завершается с кодом 2.

### Стартовый скрипт

Текстовый файл (UTF-8), по одной команде эмулятора в строке. Пустые
строки и строки, начинающиеся с `#`, пропускаются. На экране показывается
и ввод, и вывод, как в живом диалоге. Скрипт **останавливается при первой
ошибке** (или на команде `exit`).

### Команды

- `ls [-a] [путь...]` - Содержимое директорий. Без пути - текущая директория. Скрытые файлы (имя с
  точки) видны только с `-a`. Для файла печатается его имя, при нескольких путях перед каждой
  директорией выводится заголовок `путь:`
- `cd [путь]` - Смена текущей директории. Без аргумента - переход в корень `/`. Понимает абсолютные
  и относительные пути, `.` и `..`
- `cat файл...` - Выводит содержимое файлов (UTF-8; недекодируемые байты заменяются)
- `touch файл...` - Создаёт пустые файлы в VFS (только в памяти). Существующие файлы не изменяются
- `rmdir директория...` - Удаляет пустые директории (только в памяти). Нельзя удалить корень,
  текущую директорию, путь на `.` или `..`, непустую директорию
- `uptime` - Время работы эмулятора, число пользователей и нагрузка, как в UNIX
- `who` - Пользователь, терминал, время входа и имя хоста, как в UNIX
- `vfs-init` - Заменяет текущую VFS на VFS по умолчанию и **очищает содержимое директории `--vfs` на
  диске**
- `exit` - Закрывает эмулятор

Сообщения об ошибках оформлены как в UNIX, например
`cat: missing.txt: No such file or directory`,
`cd: docs: Not a directory`,
`ls: cannot access 'x': No such file or directory`,
`rmdir: failed to remove 'docs': Directory not empty`.

Команды `touch` и `rmdir` меняют только VFS в памяти. Файлы на диске
остаются нетронутыми; после перезапуска эмулятора изменения теряются.

`vfs-init` откажется очищать корень диска, домашнюю и текущую директории,
их родителей и директории с `.git`.

### Разбор команд

- Слова разделяются пробелами.
- Кавычки `"..."` и `'...'` объединяют слова в один аргумент.
- `\` экранирует следующий символ (кроме одинарных кавычек).
- Ошибки: `command not found` для неизвестной команды,
  `syntax error: ...` для незакрытой кавычки.

### Примеры VFS

В `examples/vfs/` лежат три варианта: `minimal` (один файл), `several`
(несколько файлов, скрытый файл) и `deep` (5 уровней вложенности).

## 3. Сборка и запуск тестов

Сборка не требуется. Установка инструментов разработки:

```
pip install -r requirements-dev.txt
```

Запуск эмулятора:

```
./run.sh [параметры]        (Linux / macOS)
run.bat [параметры]         (Windows)
```

Запуск тестов и проверка стиля:

```
python -m pytest
python -m flake8 src tests
```

Скрипты для проверки работы лежат в `scripts/` (`*.sh` для Linux/macOS,
`*.bat` для Windows):

- `stage2_*` - параметры командной строки и остановка скрипта на ошибке;
- `stage3_vfs_variants` - разные варианты VFS (минимальный, несколько
  файлов, 5 уровней) и неверный путь;
- `stage3_vfs_init` - `vfs-init` на **копии** VFS;
- `stage4_demo` - `ls`, `cd`, `cat`, `uptime`, `who` на разных VFS;
- `stage5_demo` - `touch` и `rmdir`; проверяет, что диск не изменился.

> Не запускайте `vfs-init` на `examples/vfs/*` напрямую: команда очищает
> директорию на диске. Восстановить примеры можно командой
> `git checkout -- examples/vfs`.

## 4. Примеры использования

```
./run.sh --vfs examples/vfs/deep --prompt "{user}:{cwd}> " \
    --script examples/startup/stage4_all.txt
```

```
[debug] --vfs    = 'examples/vfs/deep'
[debug] --prompt = '{user}:{cwd}> '
[debug] --script = 'examples/startup/stage4_all.txt'
[debug] VFS loaded: 6 dirs, 5 files
user:/> ls
README.txt  etc  home
user:/> cd home/user/docs
user:/home/user/docs> ls
archive  report.txt
user:/home/user/docs> cat report.txt
Отчёт за третий квартал 2026 года.
user:/home/user/docs> cd ../..
user:/home> cd
user:/> cat missing.txt
cat: missing.txt: No such file or directory
[script] stopped: error on line 30
```

Изменение VFS (`./run.sh` без `--vfs`, VFS по умолчанию):

```
/> ls /
etc  home  tmp
/> rmdir /tmp
/> touch /new.txt /a.txt
/> ls /
a.txt  etc  home  new.txt
/> rmdir /etc
rmdir: failed to remove '/etc': Directory not empty
```
